# 社区验证与问题反馈

Zymor 的长期效果交给社区验证；本仓库只保证基础功能和明确程序逻辑问题的修复。

## 反馈什么

- 基础功能不可用：初始化、写入、检索、上下文、dream、晋升、stale、rules、MCP；
- 明确的程序逻辑错误：错误结果、数据损坏、状态机异常；
- 安装/升级/迁移问题；
- 宿主 Hook/Skill 接入问题。

## 反馈时提供

```text
- Zymor 版本 / commit
- Python 版本
- 操作系统
- 最小复现步骤
- 期望行为 / 实际行为
- 相关日志（脱敏）
- vault 结构（不要上传私密记忆）
```

使用仓库 issue 模板；安全漏洞不要开公开 issue，见 `SECURITY.md`。

## 我们如何处理

- 基础功能 bug：进入 triage，复现后修复并补测试；
- 效果类问题：记录使用场景，不承诺内部长期 A/B；
- 宿主特有问题：优先修复通用契约，宿主专属逻辑由对应集成项目维护；
- 无法复现的问题：请求最小复现或降级为文档说明。

## 基本验证命令

```bash
uv sync --extra dev
uv run pytest -q
uv run ruff check src tests
uv run mypy src/zymor
uv run zymor doctor
```

社区可以提交脚本/记录包作为证据，但不要把未脱敏的个人记忆或密钥提交到仓库。

## 边界

- 不把 benchmark 分数当作产品价值证明；
- 不内部承诺长期生产力提升；
- 不替社区维护私有部署；
- 不因单个使用场景的偏好改变核心契约。
