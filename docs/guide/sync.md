# 云端同步

> 想要「接入一次，所有工具自动读写同一份云端记忆」，用 [`cloud.md`](cloud.md) 的云端模式。本页是另一种用法：记忆的提炼和使用都留在本地，服务器只存副本。两种用法可以共用同一台服务器，但不要对同一个库混用。
>
> 云端模式下把服务器的知识下载成本地只读副本，用 `zymor sync mirror`，见 [`cloud.md`](cloud.md) 的「本地副本」。

`zymor sync` 把本地库里的知识节点增量同步到一台远端服务器。本地库是事实源，远端只保存文件副本。

- 每次只传输内容有变化的文件，按 sha256 判断。
- 远端把副本放在独立的区域，不并入服务器自己的库，也不做提炼。
- 多台电脑同步到同一个分区时，各自的新节点会互相下载，最终每台电脑都有完整的一份。

## 配置

服务器一侧：按 [`deployment.md`](deployment.md) 启动 `zymor mcp --transport http`。同步入口 `POST /sync` 随它一起提供，使用同一个 Bearer token。

已经运行过 `zymor connect` 的电脑不需要再配置，`zymor sync` 沿用它保存的地址和 token。

没有运行过 `zymor connect` 的电脑，在 `~/.zymor/config.toml` 写：

```toml
[sync]
url = "https://memory.example.com"
```

再设置 token：

```bash
export ZYMOR_SYNC_TOKEN=<服务器的 HTTP token>
```

地址必须是 `https`。服务器使用自签证书时，设 `[sync].ca_file = "<证书路径>"`。

## 使用

```bash
zymor sync status          # 只显示差异，不传输
zymor sync                 # 先下载远端的新内容，再上传本地的新内容
zymor sync push            # 只上传
zymor sync pull            # 只下载
zymor sync --global        # 同步用户库（~/.zymor/vault），在任何目录下都可以运行
zymor sync --include-events   # 同时备份 L0 原始对话（只上传）
```

不带 `--global` 时，同步当前目录所属的库：在项目里是项目库，否则是用户库。

## 分区

远端按分区存放副本。默认分区名：

| 本地库 | 分区名 |
| --- | --- |
| 用户库 | `global` |
| 项目库 | `project-<项目名>` |

同一个项目在两台电脑上使用相同的项目名时，两边的项目库同步到同一个分区。用 `--scope <名称>` 或 `[sync].scope` 可以改分区名。

每个库各自同步，Zymor 不会把项目库的节点合并进用户库。要同步全部知识，对每个项目库各运行一次 `zymor sync`，再运行一次 `zymor sync --global`。

## 同步规则

Zymor 在本机记录上次同步时每个文件的 sha256（`<vault>/capture/sync.json`），据此判断是哪一边改了：

| 情况 | 处理 |
| --- | --- |
| 只有本地改了，或本地新增 | 上传 |
| 只有远端改了，或远端新增 | 下载 |
| 两边都改了 | 两边都不动，报告冲突 |
| 本地删除了（如 `zymor forget`） | 删除远端副本，并在远端留下删除标记 |
| 远端有删除标记，本地没再改过 | 删除本地文件 |
| 远端有删除标记，本地之后又改过 | 保留本地，重新上传，撤销删除标记 |
| 远端文件丢失，没有删除标记 | 重新上传 |

冲突时由你决定以哪一边为准：

```bash
zymor sync push --force    # 以本地为准，覆盖远端
zymor sync pull --force    # 以远端为准，覆盖本地
```

下载的节点在写入前要通过校验：内容能解析成合法节点、节点 id 和分类与路径一致、不含疑似密钥。没通过的文件被跳过，并在输出里列出。下载完成后 Zymor 自动更新索引。

## 同步的范围

| 内容 | 是否同步 |
| --- | --- |
| 知识节点（`nodes/` 下的 L2、L3、L4） | 是，双向 |
| L0 原始对话 | 默认否。加 `--include-events` 或设 `[sync].include_events = true` 后只上传，从不下载 |
| 索引、ATLAS、审计日志、待定候选池、焦点文件 | 否。索引和 ATLAS 可以在本机重建 |

L0 文件按天存放。当天的文件每次追加后都会整份重新上传。本地按保留期清理旧的 L0 文件时，远端的备份不会被删除。

## 自动运行

没有后台同步进程。两种做法任选其一：

- 定时任务：`*/30 * * * * zymor sync --global`。
- Claude Code 的 `SessionEnd` 钩子里追加一条 `zymor sync`。

下载会写本地库，需要写入锁。做梦正在运行时，有内容要下载的同步会报「写入锁被占用」，稍后重试即可。只上传时不需要锁。

## 边界

- 远端只是文件副本。服务器上的 MCP 工具检索不到这些节点。
- 没有历史版本。被覆盖或被删除的远端文件不能恢复。需要历史时，把服务器的 `sync-store/` 目录纳入 git 或定期快照。
- 冲突以整个文件为单位，不做内容合并。
- 持有 token 的一方可以读取和覆盖所有分区。
- 只读模式的服务器（`--read-only`）只允许下载，拒绝上传和删除。
